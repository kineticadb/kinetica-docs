---
title: ALTER DATA SINK
---

<a id="sql-alter-data-sink"></a>


Alters the connection parameters of an existing
[data sink](/content/sql/ddl/create-data-sink#sql-create-data-sink).

```sql title="ALTER DATA SINK Syntax"
ALTER [EXTERNAL] DATA SINK [<data sink schema name>.]<data sink name>
SET PROPERTY
    <property name> = '<property value>'[,...]
```


<Info>
Kafka *data sinks* will be validated upon creation, by default, and
will fail to be created if an authorized connection cannot be established.
</Info>


## Parameters


<AccordionGroup>

<Accordion title="EXTERNAL" id="external" defaultOpen>

Optional keyword for clarity

</Accordion>

<Accordion title="&lt;schema name&gt;" id="<schema-name>" defaultOpen>

Name of the *schema* containing the *data sink* to alter

</Accordion>

<Accordion title="&lt;data sink name&gt;" id="<data-sink-name>" defaultOpen>

Name of the *data sink* to alter

</Accordion>

<Accordion title="SET PROPERTY" id="set-property" defaultOpen>

Indicator that a comma-delimited list of alterations to make will follow.

See [Set Properties](/content/sql/ddl/alter-data-sink#sql-alter-data-sink-prop) for the complete list of properties.

</Accordion>

</AccordionGroup>


## Examples


To alter a *data sink*, `kin_dsink`, updating the timeouts:

{/* Source: /examples/sql/data_sink/data_sink.kisql (lines 44-45 47-48) */}
```sql ALTER DATA SINK Example
ALTER DATA SINK kin_dsink
SET PROPERTY
    CONNECTION TIMEOUT = '10',
    WAIT TIMEOUT = '10'
```

## Set Properties


All *data sink* properties can be altered via [ALTER DATA SINK](/content/sql/ddl/alter-data-sink#sql-alter-data-sink).
The following are the property names and descriptions to use when performing an
alteration.

<AccordionGroup>

<Accordion title="CREDENTIAL" id="credential" defaultOpen>

**Consumer:** *Any*

[Credential](/content/sql/ddl/create-credential#sql-create-credential) object to
use to authenticate to the remote consumer

</Accordion>

<Accordion title="LOCATION" id="location" defaultOpen>

**Consumer:** *Any*

Location of the *data sink*; see
[Consumer-Specific Syntax](/content/sql/ddl/create-data-sink#sql-create-data-sink-syntax) for details

</Accordion>

<Accordion title="VALIDATE" id="validate" defaultOpen>

**Consumer:** *Any*

Whether to test the connection to the *data sink* upon
creation; if `TRUE` *(default)*, the creation of a
*data sink* that cannot be connected to will fail; if
`FALSE`, the *data sink* will be created regardless
of connectivity

</Accordion>

<Accordion title="WAIT TIMEOUT" id="wait-timeout" defaultOpen>

**Consumer:** *Any* except `JDBC`

Timeout in seconds for reading from the consumer

</Accordion>

<Accordion title="CONNECTION TIMEOUT" id="connection-timeout" defaultOpen>

**Consumer:** *Any* except `JDBC`

Timeout in seconds for connecting to a consumer

</Accordion>

<Accordion title="USE_HTTPS" id="use_https" defaultOpen>

**Consumer:** `AZURE`, `GCS`, `S3`

Whether to connect to the storage provider over HTTPS or not
