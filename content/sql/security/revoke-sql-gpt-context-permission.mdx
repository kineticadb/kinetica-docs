---
title: REVOKE SQL-GPT Context Permission
---

<a id="sql-security-priv-mgmt-gpt-revoke"></a>


Permissions on [SQL-GPT contexts](/content/sql/sqlgpt/create-context#sql-gpt-create-context)
that have been [granted](/content/sql/security/grant-sql-gpt-context-permission#sql-security-priv-mgmt-gpt-grant)
directly to
[users](/content/security/sec_concepts#security-concepts-users) or
[roles](/content/security/sec_concepts#security-concepts-roles) can be revoked.

```sql title="REVOKE SQL-GPT Context Permission Syntax"
REVOKE <READ | ADMIN> [PRIVILEGES]
ON <ALL CONTEXTS [IN [SCHEMA] <schema reference>] | CONTEXT <context reference>>
FROM <user name | role name>
```

```sql title="REVOKE Create SQL-GPT Context Permission Syntax"
REVOKE CREATE [PRIVILEGES] ON CONTEXTS
[IN [SCHEMA] <schema reference>]
FROM <user name | role name>
```


## Examples


To revoke *read* access on the *SQL-GPT context* named
**example.atc_ctx** from the **ctxuser** *user*:

{/* Source: /examples/sql/sql-gpt/syntax.kisql (lines 235) */}
```sql REVOKE SQL-GPT Context Permission Example
REVOKE READ ON CONTEXT example.atc_ctx FROM ctxuser
```
