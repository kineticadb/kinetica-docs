---
title: GRANT Credential Permission
---

<a id="sql-security-priv-mgmt-cred-grant"></a>


[Credential permissions](/content/security/sec_concepts#security-concepts-permissions-credential),
which allow management of [credentials](/content/sql/ddl/create-credential#sql-create-credential),
can be granted directly to
[users](/content/security/sec_concepts#security-concepts-users) or
[roles](/content/security/sec_concepts#security-concepts-roles).

```sql title="GRANT Credential Permission Syntax"
GRANT <READ | ADMIN> [PRIVILEGES]
ON <ALL CREDENTIALS [IN [SCHEMA] <schema reference>] | CREDENTIAL <credential reference>>
TO <user name | role name> [WITH GRANT OPTION]
```

```sql title="GRANT Create Credential Permission Syntax"
GRANT CREATE [PRIVILEGES] ON CREDENTIALS
[IN [SCHEMA] <schema reference>]
TO <user name | role name> [WITH GRANT OPTION]
```

| Permission | Description |
| --- | --- |
| `ADMIN` | Modify or drop the given *credential* (includes `READ` access). |
| `READ` | Use or view the configuration of the given *credential*. |
| `<credential reference>` | The name of the credential to which access is being granted, or a wildcard expression signifying the credentials to which access is being granted.  The following forms are valid: <br/> <br/> *&lt;schema&gt;.&lt;credential&gt;*: Fully-qualified credential name in the specified schema <br/> <br/> `*.*`: All existing credentials that the granting user can see, across all schemas <br/> <br/> `*`: All existing schemas the granting user can see, which grants access to all credentials in those schemas now and in the future <br/> <br/> *&lt;schema&gt;*: All credentials in the specified schema <br/> <br/> *&lt;credential&gt;*: Credential in the default schema. If a schema exists with the same name, it will be used. To avoid this, specify the fully-qualified credential name. |
| `<schema reference>` | The schema the permission applies to (with the `ALL` or `CREATE` forms).  If the IN [SCHEMA] clause is omitted, the permission applies across all schemas, both now and in the future.  Wildcards are not permitted with the IN keyword. |
| `WITH GRANT OPTION` | Grant this permission with a [grant option](/content/security/sec_concepts#security-concepts-permissions-grant-option) to grant it to others. |


## Examples


To grant read access on the *credential* named
**auser_azure_active_dir_creds** to the **auser** *user*:

{/* Source: /examples/sql/credential/credential.kisql (lines 50) */}
```sql GRANT Credential Use Permission Example
GRANT READ ON CREDENTIAL auser_azure_active_dir_creds TO auser
```

To grant administrative access on the *credential* to the **auser** *user*:

{/* Source: /examples/sql/credential/credential.kisql (lines 63) */}
```sql GRANT Credential Administrative Permission Example
GRANT ADMIN ON CREDENTIAL auser_azure_active_dir_creds TO auser
```
