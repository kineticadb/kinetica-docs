---
title: RESTORE BACKUP
---

<a id="sql-backup-restore"></a>


Restores the given database objects & data from an existing *full*,
*incremental*, or *differential snapshot* within a
[backup](/content/sql/backup_restore/create-backup#sql-backup-create); retrieving the backed-up files at the
location accessible through the given
[data source](/content/sql/ddl/create-data-source#sql-create-data-source).

Each restored object is placed in its original *schema*.

```sql title="RESTORE BACKUP Syntax"
RESTORE BACKUP <backup name>
DATA SOURCE <data source name>
OBJECTS (<object type> = <object name>[,...])
[WITH OPTIONS (<restore option name> = '<restore option value>'[,...])]
```


## Parameters


<AccordionGroup>

</Accordion>

<Accordion title="&lt;data source name&gt;" id="<data-source-name>" defaultOpen>

*backup* files from the remote file store.

</Accordion>

<a id="sql-backup-restore-opt"></a>


## Options


The following options can be specified to further modify a *backup*
restoration.

<AccordionGroup>

<Accordion title="BACKUP_ID" id="backup_id" defaultOpen>

ID of *snapshot* from which objects will be restored.  The default is to use the most recent one.

</Accordion>

<Accordion title="CHECKSUM" id="checksum" defaultOpen>

Verify checksums calculated during back up process before restoring.  The default (`false`) is
to not verify checksums.

</Accordion>

<Accordion title="CREATE_SCHEMA_IF_NOT_EXIST" id="create_schema_if_not_exist" defaultOpen>

Whether to create the [schema](/content/sql/ddl/create-schema#sql-create-schema) containing objects being restored if it
doesn't exist.  The default (`true`) is to create the *schema* if it doesn't exist.

</Accordion>

<Accordion title="DDL_ONLY" id="ddl_only" defaultOpen>

For any table, only restore its DDL; don't restore its data.  The default (`false`) is to
restore data and DDL.

</Accordion>

<Accordion title="DRY_RUN" id="dry_run" defaultOpen>

Execute a dry run of a restoration without actually restoring any files.  The default (`false`)
is to not do a dry run.

</Accordion>

<Accordion title="RENAMED_OBJECTS_SCHEMA" id="renamed_objects_schema" defaultOpen>

If `RESTORE_POLICY` is `rename`, each existing database objects will be relocated to this
[schema](/content/sql/ddl/create-schema#sql-create-schema) if a restored database object would otherwise collide with
it.  If not specified, the *schema* name will be automatically generated, using the format:
`backup_<UUID>`.


<Info>
Specify this option when restoring via SQL; the automatically generated *schema*
name is not available to a SQL client, leaving the relocated objects difficult to find.
</Info>

</Accordion>

<Accordion title="RESTORE_POLICY" id="restore_policy" defaultOpen>

Restoration scheme to use when restoring objects that already exist.  Under the default policy,
an existing object is not replaced; it is skipped & reported as failed, and the restoration
continues with the remaining objects.


<Info>
The set of skipped objects is not available to a SQL client.  Each restoration is
recorded in the [ki_backup_history](/content/catalogs/kinetica) catalog table, with its
status & the set of objects *requested*; compare that against the database to determine
which were skipped.  To retrieve the failed objects directly, use
[/restore/backup](/content/api/rest/restore_backup_rest) instead.
</Info>

Other policy choices include:


<div>
<table class="table w-full [&_td]:min-w-[150px] [&_th]:text-left [&_td[data-numeric]]:tabular-nums">
  <thead>
  <tr>
    <th>Policy</th>
    <th>Description</th>
  </tr>
  </thead>
  <tbody>
  <tr>
    <td><code>rename</code></td>
    <td>If any object being restored already exists in the database in its corresponding [schema](/content/sql/ddl/create-schema#sql-create-schema), move all already-existing objects that would otherwise be overwritten by the restoration into another *schema*, and restore all objects to their original *schema*. The name of the *schema* holding the relocated objects is determined by <code>RENAMED_OBJECTS_SCHEMA</code>, and will be created if it doesn't exist. <Note>Applicable only to *credentials*, *data sinks*, *data sources*, *table monitors*, *SQL procedures*, *tables*, & non-temporary *views*. An object of any other type is left in place and is not restored.</Note></td>
  </tr>
  <tr>
    <td><code>replace</code></td>
    <td>If the object being restored already exists in the database in its corresponding *schema*, overwrite the existing object with it.  Objects with dependent objects will not be restored, as they are not able to be dropped before being restored due to those dependencies. Only objects in the backup are dropped; existing objects that are not in the backup are kept, so the result is a merge of the backup into the database.  To drop those as well, use <code>clean</code>. <Note>When applied to a *KiFS directory*, the target directory and all its contents will be deleted before restoring the backup content to it; this includes removing files that are not part of the restored backup.</Note></td>
  </tr>
  <tr>
    <td><code>clean</code></td>
    <td>Before restoring, drop every existing object of each object type being restored, whether or not it is in the backup, including objects that are not persisted; object types not being restored are left untouched. *Schemas* are not dropped.  A data sink generated for a *table monitor* is dropped along with the monitor, and a home directory only along with its user.  Objects created by other sessions while the restore runs are not dropped. Unlike <code>replace</code>, the clean is scoped by object type, not by name: restoring a single table drops every table in the database first, and a warning is returned when the objects to restore name specific objects of a type rather than all of them. The restore is aborted, before anything is dropped, if an object that would be dropped is still used by an object of a type that is not being restored, or cannot be dropped, such as a table locked by a backup in progress.  As *graphs*, *contexts*, *table monitors* and *SQL procedures* all depend on tables, restoring tables requires restoring each of those types of which any objects exist.  Run with <code>DRY_RUN</code> first to check this without dropping anything.  If the restore fails after the clean, the dropped objects are not put back. System objects, the data source being restored from and its credential, the user running the restore and <code>admin</code> (with their default *schemas*, home directories and resource groups), and the roles of the user running the restore are never dropped, nor are the *schemas* holding any of these. Requires system administrator permission.</td>
  </tr>
  <tr>
    <td><code>clean_all</code></td>
    <td>Before restoring, drop every existing object in the database, including users, roles, non-system *schemas* and objects that are not persisted, regardless of which objects are being restored. The restore is aborted, before anything is dropped, if an object cannot be dropped, such as a table locked by a backup in progress, or is still used by an object the clean keeps; <code>CREATE_SCHEMA_IF_NOT_EXIST</code> must not be set to <code>false</code>.  If the restore fails after the clean, the dropped objects are not put back. System objects, the data source being restored from and its credential, the user running the restore and <code>admin</code> (with their default *schemas*, home directories and resource groups), and the roles of the user running the restore are never dropped, nor are the *schemas* holding any of these. Requires system administrator permission.</td>
  </tr>
  </tbody>
</table>
</div>

## Examples


For example, to restore the `example_backup` schema from a *backup* named
`schema_backup`, copying data from a source via *data source* `restore_ds`:

{/* Source: /examples/sql/backup/backup.kisql (lines 98-100) */}
```sql RESTORE BACKUP (Schema) Example
RESTORE BACKUP schema_backup
DATA SOURCE = restore_ds
OBJECTS (ALL = example_backup)
```

To restore individual tables from a *backup* named `schema_backup`, restoring
tables that already exist into a new schema, `example_backup_restore`:

{/* Source: /examples/sql/backup/backup.kisql (lines 213-220) */}
```sql RESTORE BACKUP (Objects w/ Rename Schema) Example
RESTORE BACKUP schema_backup
DATA SOURCE = restore_ds
OBJECTS (TABLE = example_backup.employee, example_backup.product)
WITH OPTIONS
(
	RESTORE_POLICY = 'rename',
	RENAMED_OBJECTS_SCHEMA = 'example_backup_restore'
)
```
