<h2 id="fields" className="fields section-header">Fields</h2>
<span id="structfield.result" className="structfield section-header"><code>result: <a className="primitive" href="https://doc.rust-lang.org/1.98.1/std/primitive.bool.html">bool</a></code></span>
<div className="docblock">
<p>Indicates a successful retrieval.</p>
</div>
<span id="structfield.entities_int" className="structfield section-header"><code>entities\_int: <a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/vec/struct.Vec.html" title="struct alloc::vec::Vec">Vec</a>&lt;<a className="primitive" href="https://doc.rust-lang.org/1.98.1/std/primitive.i64.html">i64</a>&gt;</code></span>
<div className="docblock">
<p>Flat array of entity data for integer-identifier graphs with a repeating stride. For node entities (stride 2): \[node\_id, label\_index, …\]. For edge entities (stride 4): \[edge\_id, node1\_id, node2\_id, label\_index, …\]. Populated when the graph uses integer identifiers; empty otherwise. The label\_index is a 1-based index into the <code>labels</code> array; 0 indicates no label. When the request option ‘concise\_edge\_connectivity’ is ‘true’, this array is also used (regardless of graph identifier type) for edge entities and carries \[edge\_id, node1\_index, node2\_index, edge\_label\_index\] where node1\_index/node2\_index are 0-based positions into the node array returned from a paired node call on the same graph.</p>
</div>
<span id="structfield.entities_string" className="structfield section-header"><code>entities\_string: <a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/vec/struct.Vec.html" title="struct alloc::vec::Vec">Vec</a>&lt;<a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/string/struct.String.html" title="struct alloc::string::String">String</a>&gt;</code></span>
<div className="docblock">
<p>Flat array of entity data for name-identifier (string) graphs only. For node entities (stride 2): \[node\_name, label\_index, …\]. For edge entities (stride 4): \[edge\_id, node1\_name, node2\_name, label\_index, …\]. Populated only when the graph uses string identifiers. Empty for integer-identifier graphs (data goes to <code>entities\_int</code>) and for WKT/geo-XY graphs (data always goes to <code>entities\_double</code> — ‘POINT(x y)’ strings are never emitted). The label\_index is a string representation of a 1-based index into the <code>labels</code> array; ‘0’ indicates no label.</p>
</div>
<span id="structfield.entities_double" className="structfield section-header"><code>entities\_double: <a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/vec/struct.Vec.html" title="struct alloc::vec::Vec">Vec</a>&lt;<a className="primitive" href="https://doc.rust-lang.org/1.98.1/std/primitive.f64.html">f64</a>&gt;</code></span>
<div className="docblock">
<p>Compact double-packed payload for WKT (geo/XY) graphs. WKT graphs ALWAYS use this array — ‘POINT(x y)’ strings are never emitted anywhere. Stride 3 for nodes: \[x, y, label\_index, …\]. Stride 6 for edges (non-concise): \[edge\_id, x0, y0, x1, y1, label\_index, …\]. Empty for non-WKT graphs and when concise mode emits edges into <code>entities\_int</code> instead. label\_index/edge\_id occupy double slots (representable exactly up to 2^53). When ‘concise\_edge\_connectivity’ is ‘true’ and entity\_type is ‘node’, tombstoned (deleted) WKT slots emit \[0.0, 0.0, 0.0\] to keep position indices stable. Roughly 4x smaller on the wire than ‘POINT(x y)’ strings and avoids any client-side regex parse.</p>
</div>
<span id="structfield.entities_weight" className="structfield section-header"><code>entities\_weight: <a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/vec/struct.Vec.html" title="struct alloc::vec::Vec">Vec</a>&lt;<a className="primitive" href="https://doc.rust-lang.org/1.98.1/std/primitive.f32.html">f32</a>&gt;</code></span>
<div className="docblock">
<p>Per-edge weight values, populated only when the request option ‘include\_weights’ is ‘true’ and <code>options entity\_type</code> is ‘edge’. Stride 1, aligned 1:1 with the edge records emitted in <code>entities\_int</code> or <code>entities\_string</code> (i.e. the i-th weight corresponds to the i-th edge record). Empty when the graph has no weights component, when requesting nodes, or when the option is not set. Single-precision float matches the graph server’s native weight storage.</p>
</div>
<span id="structfield.labels" className="structfield section-header"><code>labels: <a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/vec/struct.Vec.html" title="struct alloc::vec::Vec">Vec</a>&lt;<a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/string/struct.String.html" title="struct alloc::string::String">String</a>&gt;</code></span>
<div className="docblock">
<p>Array of distinct label strings. The label\_index values in <code>entities\_int</code>, <code>entities\_string</code>, or <code>entities\_double</code> are 1-based indexes into this array; index 0 means no label.</p>
</div>
<span id="structfield.info" className="structfield section-header"><code>info: <a className="struct" href="https://doc.rust-lang.org/1.98.1/std/collections/hash/map/struct.HashMap.html" title="struct std::collections::hash::map::HashMap">HashMap</a>&lt;<a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/string/struct.String.html" title="struct alloc::string::String">String</a>, <a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/string/struct.String.html" title="struct alloc::string::String">String</a>&gt;</code></span>
<div className="docblock">
<p>Additional information map. Contains the following keys: ‘identifier\_type’ — describes the graph’s native node identifier type: ‘int’, ‘string’, or ‘wkt’ (geo/XY graph). ‘payload\_type’ — describes which array actually holds this response payload: ‘int’ (<code>entities\_int</code>), ‘string’ (<code>entities\_string</code>), or ‘double’ (<code>entities\_double</code>). WKT graphs ALWAYS use ‘double’ for both nodes and edges — ‘POINT(x y)’ strings are never emitted. In concise edge mode payload\_type is ‘int’ regardless of graph type. Clients should dispatch on ‘payload\_type’, not ‘identifier\_type’, to parse the response. ‘total\_count’ — total number of entities available in the graph for the requested entity\_type, used for pagination; this is the live (non-deleted) count by default, or the raw count (including deleted slots) when ‘concise\_edge\_connectivity’ is true for a node request. ‘status\_message’ — set to ‘Cancelled’ if the request was cancelled mid-iteration (with <code>result</code> set to false). ‘concise\_edge\_connectivity’ — set to ‘true’ when the response was produced with the concise option (edges emitted as \[edge\_id, v0\_index, v1\_index, label\_idx\] in <code>entities\_int</code>; WKT-graph nodes emitted as \[x, y, label\_idx\] in <code>entities\_double</code>; non-WKT nodes still in their native array; node output includes deleted slots to keep indices stable). ‘include\_weights’ — set to ‘true’ when <code>entities\_weight</code> is populated.</p>
</div>
