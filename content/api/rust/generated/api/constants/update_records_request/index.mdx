<div id="options.IGNORE_EXISTING_PK" className="dt constant-def"><code>pub const IGNORE\_EXISTING\_PK: &amp;str = &quot;ignore\_existing\_pk&quot;;</code></div>
<div className="dd">
<p>Specifies the record collision error-suppression policy for updating a table with a primary key, only used when primary key record collisions are rejected (update\_on\_existing\_pk is false). If set to true, any record update that is rejected for resulting in a primary key collision with an existing table record will be ignored with no error generated. If false, the rejection of any update for resulting in a primary key collision will cause an error to be reported. If the specified table does not have a primary key or if update\_on\_existing\_pk is true, then this option has no effect.</p>

<div id="options.UPDATE_ON_EXISTING_PK" className="dt constant-def"><code>pub const UPDATE\_ON\_EXISTING\_PK: &amp;str = &quot;update\_on\_existing\_pk&quot;;</code></div>
<div className="dd">
<p>Specifies the record collision policy for updating a table with a primary key. There are two ways that a record collision can occur.</p>
<p>The first is an “update collision”, which happens when the update changes the value of the updated record’s primary key, and that new primary key already exists as the primary key of another record in the table.</p>
<p>The second is an “insert collision”, which occurs when a given filter in <code>expressions</code> finds no records to update, and the alternate insert record given in <code>records\_to\_insert</code> (or <code>records\_to\_insert\_str</code>) contains a primary key matching that of an existing record in the table.</p>
<p>If update\_on\_existing\_pk is set to true, “update collisions” will result in the existing record collided into being removed and the record updated with values specified in <code>new\_values\_maps</code> taking its place; “insert collisions” will result in the collided-into record being updated with the values in <code>records\_to\_insert</code> / <code>records\_to\_insert\_str</code> (if given).</p>
<p>If set to false, the existing collided-into record will remain unchanged, while the update will be rejected and the error handled as determined by ignore\_existing\_pk. If the specified table does not have a primary key, then this option has no effect.</p>
</div>
<div id="options.UPDATE_PARTITION" className="dt constant-def"><code>pub const UPDATE\_PARTITION: &amp;str = &quot;update\_partition&quot;;</code></div>
<div className="dd">
<p>Force qualifying records to be deleted and reinserted so their partition membership will be reevaluated.</p>

<div id="options.USE_EXPRESSIONS_IN_NEW_VALUES_MAPS" className="dt constant-def"><code>pub const USE\_EXPRESSIONS\_IN\_NEW\_VALUES\_MAPS: &amp;str = &quot;use\_expressions\_in\_new\_values\_maps&quot;;</code></div>
<div className="dd">
<p>When set to true, all new values in <code>new\_values\_maps</code> are considered as expression values. When set to false, all new values in <code>new\_values\_maps</code> are considered as constants. NOTE: When true, string constants will need to be quoted to avoid being evaluated as expressions.</p>
</div>
