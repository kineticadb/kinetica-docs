<div className="docblock">
<p>Build record key from typed shard key values (optimized path - no string parsing).</p>
<p>This method uses pre-typed values from <code>ShardKeyExtractor</code> to avoid string parsing overhead for numeric types.</p>
<p><strong>Performance Note:</strong> For best performance, return shard key values in the same order as the table’s shard columns. This enables O(1) lookup instead of O(n) search.</p>
<p>Returns <code>None</code> if the table has no shard key, and fails if a value is not of a type its column accepts (see \[<code>add\_shard\_value</code>\]).</p>

<h4 className="code-header">pub fn <a href="#method.build_expression" className="fn">build\_expression</a>( &amp;self, key\_values: &amp;\[<a className="enum" href="/content/api/rust/bulk_inserter_common/enum.ShardKeyValue" title="enum gpudb_api::bulk_inserter_common::ShardKeyValue">ShardKeyValue</a>&lt;'\_&gt;\], ) -&gt; <a className="enum" href="https://doc.rust-lang.org/1.98.1/core/result/enum.Result.html" title="enum core::result::Result">Result</a>&lt;<a className="enum" href="https://doc.rust-lang.org/1.98.1/core/option/enum.Option.html" title="enum core::option::Option">Option</a>&lt;<a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/string/struct.String.html" title="struct alloc::string::String">String</a>&gt;, <a className="enum" href="/content/api/rust/errors/enum.KineticaError" title="enum gpudb_api::errors::KineticaError">KineticaError</a>&gt;</h4>
</div>
</div>
<div className="docblock">
<p>Builds a filter expression associating the given key values, one per key column in key order, with the table’s key columns.</p>
<ul>
<li><code>None</code> when the table has no key.</li>
<li>The number of values must equal the number of key columns exactly.</li>
<li>Terms are <code>&lt;column&gt; = &lt;value&gt;</code>, joined by <code>" and "</code>, and a null value is <code>is\_null(&lt;column&gt;)</code>.</li>
<li>The text types (<code>char\*</code>, <code>date</code>, <code>datetime</code>, <code>decimal</code>, <code>ipv4</code>, <code>string</code>, <code>time</code>, <code>uuid</code>) take text, written in double quotes with every embedded double quote doubled.</li>
<li><code>ulong</code> takes any value, written out as text, but only if that is the text of an unsigned long.</li>
<li><code>int</code>, <code>int8</code> and <code>int16</code> take an <code>Int</code>, <code>Int8</code> or <code>Int16</code>, <code>long</code> and <code>timestamp</code> a <code>Long</code> or <code>Timestamp</code>, <code>float</code> a <code>Float</code> and <code>double</code> a <code>Double</code>, written always with a fraction, and in <code>E</code> notation below <code>10^-3</code> and from <code>10^7</code> on (<code>1.0</code>, <code>1.0E10</code>). An <code>int8</code> or <code>int16</code> value is not range checked.</li>
<li><code>boolean</code> takes any value: a <code>Boolean</code> as <code>1</code> or <code>0</code>, a number as <code>1</code> unless it is 0 once cut to an <code>i32</code> (a long to its low 32 bits, a float or double truncated toward zero), and text as <code>1</code>.</li>
</ul>
<p>A value of another type fails.</p>
<p>Known risk: column names are written as they are, not quoted. A key column whose name needs quoting in an expression — a reserved word, or one with special characters — yields a filter the server rejects. The names come from the table’s own schema rather than from the caller, so this is not a way to inject into the filter.</p>
</div>
