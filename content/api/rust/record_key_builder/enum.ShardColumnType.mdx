<div className="docblock">
<p>The type of a shard-key column, resolved once from the table schema.</p>
<p>This exists so the mapping from column type to key encoding is a <code>match</code> on a fieldless-ish enum rather than on a <code>&amp;str</code>. Both the ingest and look-up paths dispatch through \[<code>add\_shard\_value</code>\], and an enum makes a missing arm a compile error in both.</p>
<p>It was a <code>String</code> matched with <code>match ….as\_str()</code>, which meant every dispatch needed a <code>\_</code> catch-all — and the catch-all silently absorbed <code>decimal</code> and <code>ulong</code> on the look-up path, hashing them as strings while ingest encoded them numerically. Records went to one rank and look-ups to another.</p>
<p>The decimal and char parameters live in the variants rather than in side tables keyed by column index, so a type can no longer be separated from the parameters it needs to encode.</p>
