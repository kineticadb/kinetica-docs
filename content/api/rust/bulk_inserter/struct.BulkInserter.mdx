<p>Shard-aware high-performance bulk inserter.</p>
<p>Routes records to the correct worker based on shard key computation, enabling true multi-head ingest. Uses <code>serde\_avro\_fast</code> for fast Avro encoding and rayon for parallel processing.</p>
<p>It also provides:</p>
<ul>
<li>Support for insert options (update\_on\_existing\_pk, etc.)</li>
<li>Permission checking before insertion</li>
<li>Table replication detection (replicated tables use head node only)</li>
<li>Multi-head ingest configuration</li>
<li>Retry logic with configurable max retries</li>
</ul>
<h2 id="ha-failover-safety">HA Failover Safety</h2>
<p>This implementation uses <code>ArcSwap</code> for lock-free atomic updates of routing state during HA failover. This ensures:</p>
<ul>
<li>No race conditions when routing table changes during insert operations</li>
<li>No out-of-bounds indexing from stale routing data</li>
<li>Records are always routed using consistent, up-to-date routing information</li>
</ul>

<div className="docblock">
<p>Inserts a single record with shard-aware routing.</p>
<p>The record’s shard key is computed using <code>ShardKeyExtractor::shard\_key\_values()</code>, and the record is routed to the worker that owns the corresponding shard.</p>
<h5 id="errors-1">Errors</h5>
<p>Returns an error if the record cannot be routed — see <a href="/content/api/rust/bulk_inserter/struct.BulkInserter#method.route_to_worker" title="method gpudb_api::bulk_inserter::BulkInserter::route_to_worker"><code>Self::route\_to\_worker</code></a>. The record is not queued in that case, and comes back in the <a href="/content/api/rust/bulk_inserter/struct.QueueError" title="struct gpudb_api::bulk_inserter::QueueError"><code>QueueError</code></a>.</p>
<p>Also returns an error after <a href="/content/api/rust/bulk_inserter/struct.BulkInserter#method.close" title="method gpudb_api::bulk_inserter::BulkInserter::close"><code>close</code></a> when this record fills a batch: the batch cannot be sent, and its records come back.</p>
<h5 id="ha-failover-safety-1">HA Failover Safety</h5>
<p>This method uses <code>ArcSwap::load()</code> to get the current routing state, which provides:</p>
<ul>
<li>Lock-free atomic read of the routing configuration</li>
<li>Consistent routing even during HA failover (no torn reads)</li>
<li>No race conditions with concurrent routing updates</li>
</ul>
<p>A JSON inserter whose <a href="/content/api/rust/json_records/struct.JsonOptions" title="struct gpudb_api::json_records::JsonOptions"><code>JsonOptions</code></a> ask for it first checks that the record is a JSON object.</p>

<h4 className="code-header">pub fn <a href="#method.insert_batch" className="fn">insert\_batch</a>(&amp;self, records: <a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/vec/struct.Vec.html" title="struct alloc::vec::Vec">Vec</a>&lt;T&gt;) -&gt; <a className="enum" href="https://doc.rust-lang.org/1.98.1/core/result/enum.Result.html" title="enum core::result::Result">Result</a>&lt;<a className="primitive" href="https://doc.rust-lang.org/1.98.1/std/primitive.unit.html">()</a>, <a className="struct" href="/content/api/rust/bulk_inserter/struct.QueueError" title="struct gpudb_api::bulk_inserter::QueueError">QueueError</a>&lt;T&gt;&gt;</h4>
</div>
</div>
<div className="docblock">
<p>Inserts a batch of records with shard-aware routing.</p>
<p>This method is more efficient than calling <code>insert()</code> in a loop because:</p>
<ol>
<li>Worker indices are computed in parallel using rayon</li>
<li>Records are grouped by destination before any lock is taken</li>
<li>Each destination’s queue is locked once per call, not once per record</li>
</ol>
<p>The records go into the calling thread’s stripe of each queue, as <code>insert</code> puts them, and a batch is sent each time that stripe reaches the batch size. No batch is larger than the batch size.</p>
<h5 id="arguments-3">Arguments</h5>
<ul>
<li><code>records</code> - A vector of records to insert. Each record will be wrapped in Arc internally.</li>
</ul>
<h5 id="errors-2">Errors</h5>
<p>The records before the first that cannot be routed are queued, and that record and every one after it come back in the <a href="/content/api/rust/bulk_inserter/struct.QueueError" title="struct gpudb_api::bulk_inserter::QueueError"><code>QueueError</code></a> with its error. A list whose JSON does not validate is not queued at all, and comes back whole.</p>
<h5 id="example-1">Example</h5>
<div>

```rust
let records: Vec<MyRecord> = (0..100_000)
    .map(|i| MyRecord { id: i, name: format!("name_{}", i) })
    .collect();
inserter.insert_batch(records)?;
```

</div>

<a className="src" href="https://github.com/kineticadb/kinetica-api-rust/blob/master/crates/gpudb-api/src/bulk_inserter.rs#L3138-L3164">Source</a>
<h4 className="code-header">pub async fn <a href="#method.close" className="fn">close</a>(&amp;self) -&gt; <a className="enum" href="https://doc.rust-lang.org/1.98.1/core/result/enum.Result.html" title="enum core::result::Result">Result</a>&lt;<a className="primitive" href="https://doc.rust-lang.org/1.98.1/std/primitive.unit.html">()</a>, <a className="enum" href="/content/api/rust/errors/enum.KineticaError" title="enum gpudb_api::errors::KineticaError">KineticaError</a>&gt;</h4>
</div>
</div>
<div className="docblock">
<p>Closes the BulkInserter, flushing all records and waiting for completion.</p>
<p>This method:</p>
<ol>
<li>Flushes all buffered records to the flush workers</li>
<li>Waits for all pending batches to complete</li>
<li>Stops the flush workers and the timed flush</li>
</ol>
<p>The inserter cannot send anything afterwards: an insert still buffers, but one that fills a batch, or a <code>flush()</code> with records buffered, fails.</p>
<p><strong>IMPORTANT</strong>: This method will wait indefinitely until all pending batches complete. It only returns when:</p>
<ol>
<li>All records have been successfully inserted, OR</li>
<li>All records have either succeeded or failed (with errors queued)</li>
</ol>
<p>Failed records are tracked in the error queue and can be retrieved via <code>drain\_errors()</code>. The method guarantees that <code>inserted + updated + failed = queued</code>.</p>
<h5 id="returns">Returns</h5>
<p>Returns <code>Ok(())</code> when all batches have completed (success or failure). Check <code>error\_count()</code> or <code>drain\_errors()</code> to see if any records failed.</p>
</div>
