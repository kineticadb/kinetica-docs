<div className="docblock">
<p>A SQLx client that automatically batches INSERT statements and routes them through <code>BulkInserter&lt;GenericRecord&gt;</code> for high-performance shard-aware ingestion.</p>
<p>This client intercepts INSERT statements executed in a loop, accumulates them, and flushes them through the high-performance <code>BulkInserter</code> when the batch size is reached. Non-INSERT statements are executed immediately via SQLx.</p>
<h2 id="features">Features</h2>
<ul>
<li><strong>Auto-batching</strong>: INSERT statements are automatically accumulated</li>
<li><strong>Shard-aware routing</strong>: Uses <code>BulkInserter&lt;GenericRecord&gt;</code> for multi-head ingest</li>
<li><strong>Mixed statements</strong>: SELECT, CREATE, etc. work normally alongside INSERTs</li>
<li><strong>Performance</strong>: Achieves high throughput for bulk INSERT operations</li>
</ul>
<h2 id="example">Example</h2>
<div>

```rust
use gpudb_api::sqlx_support::{BatchingSqlxClient, connect};
use gpudb_api::{Kinetica, KineticaOptions};
use std::sync::Arc;

// The SQLx pool for other statements, and the HTTP API client INSERT
// batches are flushed through
let pool = connect("localhost", "admin", "password").await?;
let mut options = KineticaOptions::new();
options.set_username("admin").set_password("password");
let kinetica = Arc::new(Kinetica::new(vec!["http://localhost:9191".to_string()], options).await?);

let mut client = BatchingSqlxClient::new(pool, kinetica, 10000, 8);

// Execute INSERT statements in a loop - they get auto-batched
for i in 0..100000 {
    client.execute(&format!(
        "INSERT INTO my_table (id, value) VALUES ({}, {})", i, i * 10
    )).await?;
}

// Flush remaining records and get stats
let stats = client.close().await?;
println!("Inserted {} records at {:.0} rec/sec",
    stats.records_inserted, stats.records_per_second);
```
