<p>High-level SQL client that wraps Kinetica with result parsing.</p>
<p><code>SqlClient</code> executes SQL through Kinetica’s <code>/execute/sql</code> endpoint and returns <a href="/content/api/rust/sql/struct.SqlResult" title="struct gpudb_api::sql::SqlResult"><code>SqlResult</code></a>s, with helpers for paging through large result sets.</p>
<h2 id="example">Example</h2>
<div>

```rust
use gpudb_api::{Kinetica, KineticaOptions, SqlClient};
use std::sync::Arc;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let options = KineticaOptions::new();
    let kinetica = Arc::new(
        Kinetica::new(vec!["http://localhost:9191".to_string()], options).await?
    );

    let client = SqlClient::new(kinetica);

    // Execute a SELECT query
    let result = client.execute("SELECT * FROM my_table LIMIT 10").await?;
    println!("Found {} records", result.total_records());

    // Fetch a specific page
    let page = client.execute_paged("SELECT * FROM my_table ORDER BY id", 100, 50).await?;

    Ok(())
}
```

<div className="docblock">
<p>Fetch the next page of results using a paging table</p>
<p>When a query returns <code>has\_more\_records = true</code>, Kinetica creates a temporary paging table containing the full result set. Use this method to fetch subsequent pages from that paging table.</p>
<h5 id="arguments">Arguments</h5>
<ul>
<li><code>paging\_table</code> - The paging table name from <code>SqlResult::paging\_table()</code></li>
<li><code>offset</code> - The offset within the paging table to start fetching from</li>
<li><code>limit</code> - The maximum number of records to fetch</li>
</ul>
<h5 id="example-5">Example</h5>
<div>

```rust
use gpudb_api::SqlClient;

// Initial query with a limit
let mut result = client.execute_paged("SELECT * FROM large_table", 0, 1000).await?;
let mut all_rows = result.rows()?.to_vec();

// Fetch remaining pages if there are more records
let paging_table = result.paging_table().map(|s| s.to_string());
if let Some(pt) = paging_table {
    let mut offset = 1000i64;
    while result.has_more() {
        result = client.fetch_next_page(&pt, offset, 1000).await?;
        all_rows.extend(result.rows()?.to_vec());
        offset += 1000;
    }
}
```

<p>Execute a query and iterate through all pages automatically</p>
<p>This method handles pagination transparently, fetching all pages from the paging table and returning an iterator over all results.</p>
<p><strong>Warning</strong>: This loads all results into memory. For very large result sets, consider using <code>execute\_paged</code> and <code>fetch\_next\_page</code> to process results in batches.</p>
<h5 id="arguments-1">Arguments</h5>
<ul>
<li><code>sql</code> - The SQL query to execute</li>
<li><code>page\_size</code> - The number of records to fetch per page</li>
</ul>
<h5 id="example-6">Example</h5>
<div>

```rust
use gpudb_api::SqlClient;

// Fetch all records, 10000 at a time
let mut result = client.execute_all("SELECT * FROM large_table", 10000).await?;

println!("Total records fetched: {}", result.row_count()?);

for row in result.rows()? {
    let id: i64 = row.get("column_1")?;
    // Process each row...
}
```

<p>Execute a query and process results page by page with a callback</p>
<p>This is the most memory-efficient way to process large result sets, as it only loads one page at a time.</p>
<h5 id="arguments-2">Arguments</h5>
<ul>
<li><code>sql</code> - The SQL query to execute</li>
<li><code>page\_size</code> - The number of records to fetch per page</li>
<li><code>callback</code> - A function called for each page of results</li>
</ul>
<h5 id="example-7">Example</h5>
<div>

```rust
use gpudb_api::SqlClient;

let mut total_processed = 0u64;

client.execute_paginated(
    "SELECT * FROM large_table",
    10000,
    |mut page, page_num| {
        println!("Processing page {}", page_num);
        for row in page.rows()? {
            let id: i64 = row.get("column_1")?;
            // Process row...
        }
        Ok(true) // Return false to stop pagination early
    }
).await?;
```
