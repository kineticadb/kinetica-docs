<p>Create a new job to be executed asynchronously</p>
<p>Create a job which will run asynchronously. The response returns a job ID, which can be used to query the status and result of the job. The status and the result of the job upon completion can be requested by <code>/get/job</code>.</p>
<h5 id="arguments-135">Arguments</h5>
<ul>
<li><code>endpoint</code> - Indicates which endpoint to execute, e.g. ‘/alter/table’.</li>
<li><code>request\_encoding</code> - The encoding of the request payload for the job.</li>
<li><code>data</code> - Binary-encoded payload for the job to be run asynchronously. The payload must contain the relevant input parameters for the endpoint indicated in <code>endpoint</code>. Please see the documentation for the appropriate endpoint to see what values must (or can) be specified. If this parameter is used, then <code>request\_encoding</code> must be binary or snappy.</li>
<li><code>data\_str</code> - JSON-encoded payload for the job to be run asynchronously. The payload must contain the relevant input parameters for the endpoint indicated in <code>endpoint</code>. Please see the documentation for the appropriate endpoint to see what values must (or can) be specified. If this parameter is used, then <code>request\_encoding</code> must be json.</li>
</ul>
