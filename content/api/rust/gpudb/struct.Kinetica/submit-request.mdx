<div className="docblock">
<p>Submits a request directly to a specific URL without HA failover.</p>
<p>This is the low-level method used internally by <code>submit\_request</code> and by bulk inserters that handle their own routing.</p>
<h5 id="arguments-3">Arguments</h5>
<ul>
<li><code>url</code> - Full URL including endpoint</li>
<li><code>req\_schema</code> - Pre-parsed Avro schema for the request</li>
<li><code>resp\_schema</code> - Pre-parsed Avro schema for the response</li>
<li><code>request</code> - The request object</li>
</ul>
<h5 id="performance-1">Performance</h5>
<p>This is the fastest method, saving \~5-10ms per request by avoiding all schema parsing. Critical for bulk insert performance.</p>
<h5 id="compression">Compression</h5>
<p>The payload is Snappy-compressed only when <code>options.use\_snappy</code> is true <span className="em">and</span> the request type opts in via <a href="/content/api/rust/trait.KineticaRecord#method.use_compression" title="associated function gpudb_api::KineticaRecord::use_compression"><code>KineticaRecord::use\_compression</code></a>, which the generator enables for <code>/insert/records</code> and <code>/update/records</code> alone. Compressing a two-field <code>has\_table</code> request costs more than it saves.</p>
<p>Payloads above <a href="/content/api/rust/gpudb/index#constant.MAX_SNAPPY_COMPRESSION_SIZE" title="constant gpudb_api::gpudb::MAX_SNAPPY_COMPRESSION_SIZE"><code>MAX\_SNAPPY\_COMPRESSION\_SIZE</code></a> are sent uncompressed.</p>
