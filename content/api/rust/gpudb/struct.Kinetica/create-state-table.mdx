<p>Create a table that holds materialized view state</p>
<p>Creates a state table in a materialized view allowing a materialized view to maintain state between refreshes. The state table must be a materialized view member. The state table can be part of a feedback loop including input\_table\_name. To facilitate such feedback loops the create\_state\_table can be called before the input\_table\_name is created but must be created after init\_table\_name is created. During the initial call to create the state table init\_table\_name is copied to table\_name, setting the initial state output of the table. On refresh the create\_state\_table runs before the endpoint that creates the input\_table\_name and copies the input\_table\_name to table\_name, setting the state to the version of the input\_table from the last refresh. A materialized view is not complete (ready to refresh and query) until both the root table of the view is created and all the input tables to the state tables have been created.</p>
<h5 id="arguments-151">Arguments</h5>
<ul>
<li><code>table\_name</code> - Name of the table to be created.</li>
<li><code>input\_table\_name</code> - Name of the input table to be copied to the output table on refresh.</li>
<li><code>init\_table\_name</code> - Name of the initialization table to be copied to the output table during materialized view creation.</li>
</ul>
