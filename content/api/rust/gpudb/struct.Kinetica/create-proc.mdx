<div className="docblock">
<p>Create a proc</p>
<p>Creates an instance (proc) of the user-defined functions (UDF) specified by the given command, options, and files, and makes it available for execution.</p>
<h5 id="arguments-141">Arguments</h5>
<ul>
<li>
<p><code>proc\_name</code> - Name of the proc to be created. Must not be the name of a currently existing proc.</p>
</li>
<li>
<p><code>execution\_mode</code> - The execution mode of the proc.</p>
</li>
<li>
<p><code>files</code> - A map of the files that make up the proc. The keys of the map are file names, and the values are the binary contents of the files. The file names may include subdirectory names (e.g. ‘subdir/file’) but must not resolve to a directory above the root for the proc.</p>
<p>Files may be loaded from existing files in KiFS. Those file names should be prefixed with the uri kifs:// and the values in the map should be empty</p>
</li>
<li>
<p><code>command</code> - The command (excluding arguments) that will be invoked when the proc is executed. It will be invoked from the directory containing the proc <code>files</code> and may be any command that can be resolved from that directory. It need not refer to a file actually in that directory; for example, it could be ‘java’ if the proc is a Java application; however, any necessary external programs must be preinstalled on every database node. If the command refers to a file in that directory, it must be preceded with ‘./’ as per Linux convention. If not specified, and exactly one file is provided in <code>files</code>, that file will be invoked.</p>
</li>
<li>
<p><code>args</code> - An array of command-line arguments that will be passed to <code>command</code> when the proc is executed.</p>
</li>
</ul>
