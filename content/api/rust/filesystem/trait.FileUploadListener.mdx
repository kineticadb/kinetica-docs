<p>Listener trait for file upload progress callbacks.</p>
<p>Implement this trait to receive notifications about upload progress, including per-part completion for multi-part uploads.</p>
<h2 id="example">Example</h2>
<div>

```rust
use gpudb_api::filesystem::{FileUploadListener, OperationResult};

struct MyUploadListener;

impl FileUploadListener for MyUploadListener {
    fn on_multi_part_upload_complete(&self, results: Vec<OperationResult>) {
        println!("Multi-part upload complete with {} parts", results.len());
    }

    fn on_part_upload(&self, result: OperationResult) {
        if let Some(info) = &result.upload_info {
            println!("Uploaded part {} of {}", info.upload_part_number, info.total_parts);
        }
    }

    fn on_full_file_upload(&self, result: OperationResult) {
        if result.successful {
            println!("Uploaded: {:?}", result.full_file_names);
        } else {
            println!("Upload error: {:?}", result.error_message);
        }
    }
}
```

</div>
</div>
<div className="docblock">
<p>Called when all parts of a multi-part upload have been completed.</p>
<p>The list holds a result for every stage of the job, in order: the initiating stage, one per uploaded part, and the completing stage. Only the completing stage names the uploaded file in <code>full\_file\_names</code>. Use <code>upload\_info</code> to tell the stages apart.</p>
<h5 id="arguments">Arguments</h5>
<ul>
<li><code>results</code> - List of results for each stage of the upload</li>
</ul>
</div>
</div>

<div className="docblock">
<p>Called whenever a single part of a multi-part upload has been completed.</p>
<p>This is useful for tracking progress during large file uploads. It is called for the data parts only, not for the initiating or completing stages.</p>
<h5 id="arguments-1">Arguments</h5>
<ul>
<li><code>result</code> - Result of the part upload</li>
</ul>
</div>
</div>

<div className="summary">
<div id="tymethod.on_full_file_upload" className="section method">
<a className="src" href="https://github.com/kineticadb/kinetica-api-rust/blob/master/crates/gpudb-api/src/filesystem/listeners.rs#L88">Source</a>
<h4 className="code-header">fn <a href="#tymethod.on_full_file_upload" className="fn">on\_full\_file\_upload</a>(&amp;self, result: <a className="struct" href="/content/api/rust/filesystem/struct.OperationResult" title="struct gpudb_api::filesystem::OperationResult">OperationResult</a>)</h4>
</div>
</div>
<div className="docblock">
<p>Called for each batch of whole files sent in one request, as it finishes, and for each file that could not be read to be sent.</p>
<p>For a batch sent, <code>full\_file\_names</code> lists its files and <code>file\_name</code> is empty; if the request failed, <code>successful</code> is false and <code>error\_message</code> says why. For a file that could not be read, <code>file\_name</code> is its local name and <code>error\_message</code> says why.</p>
<h5 id="arguments-2">Arguments</h5>
<ul>
<li><code>result</code> - Result of the upload operation</li>
</ul>
</div>
</div>

<h4 className="code-header">fn <a href="#method.on_multi_part_upload_cancel" className="fn">on\_multi\_part\_upload\_cancel</a>(&amp;self, results: <a className="struct" href="https://doc.rust-lang.org/1.98.1/alloc/vec/struct.Vec.html" title="struct alloc::vec::Vec">Vec</a>&lt;<a className="struct" href="/content/api/rust/filesystem/struct.OperationResult" title="struct gpudb_api::filesystem::OperationResult">OperationResult</a>&gt;)</h4>
</div>
</div>
<div className="docblock">
<p>Called when a multi-part upload was aborted because one of its stages failed after it had been initiated.</p>
<p>The list holds a result for every stage that completed before the failure, followed by the cancelling stage. It is informational only: the failure is also reported in the upload’s returned error. Not called when the cancel request itself fails. By default it does nothing.</p>
<h5 id="arguments-3">Arguments</h5>
<ul>
<li><code>results</code> - List of results for each stage, ending with the cancel</li>
</ul>
