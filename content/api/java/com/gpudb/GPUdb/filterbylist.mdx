<h3>filterByList</h3>
<div className="member-signature"><span className="modifiers">public</span>&nbsp;<span className="return-type"><a href="/content/api/java/com/gpudb/protocol/FilterByListResponse" title="class in com.gpudb.protocol">FilterByListResponse</a></span>&nbsp;<span className="element-name">filterByList</span><wbr /><span className="parameters">(<a href="/content/api/java/com/gpudb/protocol/FilterByListRequest" title="class in com.gpudb.protocol">FilterByListRequest</a>&nbsp;request)</span> throws <span className="exceptions"><a href="/content/api/java/com/gpudb/GPUdbException" title="class in com.gpudb">GPUdbException</a></span></div>
<div className="block">
Calculates which records from a table have values in the given list for the corresponding column. The operation is synchronous, meaning that a response will not be returned until all the objects are fully available. The response payload provides the count of the resulting set. A new resultant set (view) which satisfies the input filter specification is also created if a <a href="/content/api/java/com/gpudb/protocol/FilterByListRequest#getViewName()"><code>viewName</code></a> is passed in as part of the request. 
<p> For example, if a type definition has the columns 'x' and 'y', then a filter by list query with the column map {"{"}"x":\["10.1", "2.3"\], "y":\["0.0", "-31.5", "42.0"\]{"}"} will return the count of all data points whose x and y values match both in the respective x- and y-lists, e.g., "x = 10.1 and y = 0.0", "x = 2.3 and y = -31.5", etc. However, a record with "x = 10.1 and y = -31.5" or "x = 2.3 and y = 0.0" would not be returned because the values in the given lists do not correspond.</p>
