<h1 id="kinetica-nodejs-api" className="tsd-anchor-link">Kinetica Node.js API</h1>
<p>The Node.js API is published to npm as <code>@kinetica/gpudb-api</code>:</p>
<div>

```
npm install @kinetica/gpudb-api
```

</div>
<p>Both <code>require</code> and <code>import</code> resolve to it:</p>
<div>

```
const { GPUdb } = require('@kinetica/gpudb-api');      // CommonJS

import GPUdb from '@kinetica/gpudb-api';               // ES modules (default export)
```

</div>
<div>

```
const gpudb = new GPUdb('http://localhost:9191', { username: 'admin', password: 'password' });
const response = await gpudb.show_system_properties({});
```

</div>
<p>Each endpoint is available in two forms, both returning a <code>Promise</code> and both accepting an optional callback:</p>
<ul>
<li>positional parameters, e.g. <code>admin\_add\_host(host\_address, options)</code></li>
<li>a single request object, e.g. <code>admin\_add\_host\_request({"{"} host\_address, options {"}"})</code></li>
</ul>
<p>Node.js 16 or later is required; 18 or later is recommended.</p>
<h2 id="compatibility-with" className="tsd-anchor-link">Compatibility with <code>@kinetica/gpudb</code></h2>
<p><code>@kinetica/gpudb</code>, the former Node.js API, is now a compatibility wrapper around <code>@kinetica/gpudb-api</code>, kept so that existing code keeps working unchanged:</p>
<div>

```
const GPUdb = require('@kinetica/gpudb');      // the module is the constructor, as before
```

</div>
<p>It has no API of its own: it is the same <code>GPUdb</code> class, pinned to the same version, with everything the old API hung off the constructor (<code>GPUdb.Type</code>, <code>GPUdb.RingList</code>, <code>GPUdb.FileHandler</code>, <code>GPUdb.encode</code> / <code>decode</code>, <code>GPUdb.END\_OF\_SET</code>, <code>GPUdb.api\_version</code>) still in place. New code should use <code>@kinetica/gpudb-api</code> directly.</p>
<p>The source is on <a href="https://github.com/kineticadb/kinetica-api-typescript">GitHub</a>.</p>
</div>
</div>
