<h3 className="tsd-anchor-link" id="encoding"><code className="tsd-tag">Optional</code><span>encoding</span></h3>
<div className="tsd-signature"><span className="tsd-kind-property">encoding</span><span className="tsd-signature-symbol">?:</span> <span className="tsd-signature-type">&quot;binary&quot;</span> <span className="tsd-signature-symbol">|</span> <span className="tsd-signature-type">&quot;json&quot;</span></div>
<div className="tsd-comment tsd-typography">
<p>How requests and responses are encoded: <code>'json'</code>, the default, or <code>'binary'</code> for Avro, the encoding the Java and Python APIs use. Also reachable as <code>GPUdb.ENCODING.{"{"}JSON,BINARY{"}"}</code>.</p>
<p>Avro payloads are smaller and quicker to encode and decode, which counts most when inserting and reading records. Under <code>'binary'</code>:</p>
<ul>
<li>Records passed to <code>insert\_records</code> and <code>update\_records</code> are encoded with the table's type. The client looks it up with <code>show\_table</code> on the first insert into each table and caches it; see <a href="/content/api/nodejs/classes/GPUdb/clear-type-cache#clear_type_cache" className="tsd-kind-method">GPUdb.clear\_type\_cache</a>.</li>
<li>Records from <code>get\_records</code>, and the column-major data of <code>execute\_sql</code>, <code>aggregate\_group\_by</code>, <code>aggregate\_unique</code>, <code>aggregate\_unpivot</code> and <code>get\_records\_by\_column</code>, are decoded with the schema the server returns alongside them.</li>
<li>Values must match their column types exactly. A number given for a string column, or a record missing a non-nullable column, is rejected with an <code>AvroError</code> naming the field, before anything is sent.</li>
<li>A long outside Number's safe-integer range decodes to a <code>bigint</code>, in records and response fields alike, rather than losing precision. Note that <code>JSON.stringify</code> throws on a <code>bigint</code>.</li>
<li>Infinity, -Infinity and NaN decode as numbers, where JSON returns them as quoted strings. <code>force\_infinity\_nan\_conversion\_to\_null</code> turns them into null under either encoding.</li>
<li>A bytes column decodes to a <code>Uint8Array</code>.</li>
<li>Endpoints in <code>JSON\_ONLY\_ENDPOINTS</code> (file transfer, jobs, procs, visualization) stay JSON. So does the record data of <code>get\_records\_by\_series</code> and <code>get\_records\_from\_collection</code>, which travels as JSON inside the Avro envelope.</li>
</ul>
<p>A custom <a href="#transport" className="tsd-kind-property">GPUdbOptions.transport</a> is handed binary request bodies in <code>HttpRequestOptions.bytes</code> rather than <code>body</code>, and must send them unchanged.</p>
</div>

<div className="section tsd-panel tsd-member">
<h3 className="tsd-anchor-link" id="job_endpoints"><code className="tsd-tag">Optional</code><span>job\_endpoints</span></h3>
<div className="tsd-signature"><span className="tsd-kind-property">job\_endpoints</span><span className="tsd-signature-symbol">?:</span> <span className="tsd-signature-type">boolean</span> <span className="tsd-signature-symbol">|</span> <span className="tsd-signature-type">string</span><span className="tsd-signature-symbol">\[\]</span></div>
<div className="tsd-comment tsd-typography">
<p>Endpoints to submit through <code>/create/job</code> and poll, rather than calling directly. <code>false</code>, the default, calls every endpoint directly.</p>
<p>A long ALTER can outlast a proxy's idle timeout, and running it as a job keeps the HTTP request short. That only helps where such a proxy exists: a client talking to Kinetica directly pays two extra round trips, and <a href="#job_timeout" className="tsd-kind-property">JOB\_POLL\_INTERVAL</a> is 5 s, so an ALTER that finishes in milliseconds either costs one extra request or waits out a full poll interval. Off by default for that reason, and because neither the JavaScript nor the Python API wraps these endpoints -- a client that did so silently would diverge from every other Kinetica API.</p>
<p><code>true</code> uses <a href="/content/api/nodejs/classes/GPUdb/static-default-job-endpoints#default_job_endpoints" className="tsd-kind-property">GPUdb.DEFAULT\_JOB\_ENDPOINTS</a>. An array names the endpoint paths to wrap, for a deployment whose proxy cuts off other endpoints too.</p>
<p>Set <a href="#job_timeout" className="tsd-kind-property">GPUdbOptions.job\_timeout</a> alongside this, or a job that never finishes is polled forever.</p>

<h3 className="tsd-anchor-link" id="job_timeout"><code className="tsd-tag">Optional</code><span>job\_timeout</span></h3>
<div className="tsd-signature"><span className="tsd-kind-property">job\_timeout</span><span className="tsd-signature-symbol">?:</span> <span className="tsd-signature-type">number</span></div>
<div className="tsd-comment tsd-typography">
<p>How long to keep polling a job-wrapped endpoint, in milliseconds. 0, the default, means no deadline.</p>
<p><code>timeout</code> bounds each individual HTTP request; it does not bound the polling loop behind <code>/alter/table</code>, which would otherwise wait for a job that never finishes with no way for the caller to give up. This is a separate option rather than an inheritance of <code>timeout</code> because outlasting a per-request timeout is the whole reason those endpoints are wrapped in a job -- an ALTER over a large table is expected to take longer.</p>
<p>On expiry the call rejects. The job itself keeps running on the server.</p>
</div>

<p>Largest response body to accept, in bytes. 0, the default, means no ceiling.</p>
<p>A single unbounded <code>execute\_sql</code> can return more than the process has memory for, and the failure that follows is an out-of-memory kill rather than a caught error. With this set the read is abandoned as soon as the body passes the limit and the call rejects with a <code>ResponseTooLargeError</code>, which names the limit and what was received.</p>
<p>The request is not retried against another URL: an oversized result follows from the query, not from the node that served it.</p>
